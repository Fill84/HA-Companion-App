# Self-registration upgrade verification (26 September 2026)

Desktop app **1.0.6** and Home Assistant integration **1.0.12** are published in their separate GitHub repositories. Integration 1.0.12 was installed through HACS on the live server.

The integration was installed on the live Home Assistant 2026.9.3 server after backing up its config entries, device registry, entity registry, integration storage and component code. It was then installed through HACS from the 1.0.12 release tag and HA was restarted again. HACS reports installed and latest version 1.0.12; the integration reports 1.0.12 through its authenticated registration endpoint. Its config-flow handler is absent from Home Assistant's manual Add picker. The legacy empty `Desktop App` hub config entry was removed through Home Assistant's own API. After another Home Assistant restart, only the real Phill-PC and Beast-Unit entries remained. Their config-entry IDs, device IDs and webhook IDs were unchanged, and all **109** existing `(entity_id, unique_id, config_entry_id)` identities matched the pre-upgrade registry exactly.

The 1.0.6 Windows x64 NSIS installer was installed on Phill-PC and Beast-Unit. Installer SHA-256: `CAA94585725EA01EBF7569993AEEEF60F98BA17AAFADDA7768736ED2A60535F5`; both installed executables matched SHA-256 `A06C0F61509415ED308AA0D57914E62AE50735766304E08BE17795FA4C2AB228`. Both existing desktop device and webhook IDs were retained, the GUI ran in an interactive session, and `HaCompanionSensors` and `PawnIO` were running. The HA recorder received new numeric CPU usage and temperature values from both computers after the upgrade and after the final HA restart. Their Online entities returned to `on` after the next update cycle.

After the official cross-platform release workflow passed, its Windows installer was also installed on both Windows hosts. Release-installer SHA-256: `A918C4BF9E148DB95BD42139155272D26DE32E504D9B1F9FD772BE674E8E77C6`; both installed executables matched SHA-256 `4CEC43611873C77F471BACE1EA9468AEFC9484D2B991F785BB8952C6ED9C911A` and reported version 1.0.6. The same device and webhook IDs survived, both sensor services remained running, both Online entities stayed `on`, and HA received fresh numeric CPU usage and temperature values from both computers. The 109 existing entity identities still matched the original backup.

The Rust unit suite passed 49 tests (three hardware/OS-dependent tests ignored), the integration suite passed 46 tests, the frontend suite passed 20 tests after removing a stale fixed sensor count, and Clippy passed with warnings denied. An isolated Home Assistant 2026.9.3 instance additionally exercised first and second device registration through HA's built-in config-flow API, webhook sensor updates, persistence after restart and recovery of an interrupted first registration. No clean user-profile install, macOS/Linux interactive runtime test or long-duration soak test is claimed here.

The published release workflow passed on Windows, macOS and Linux. Its seven downloadable artifacts were checked against `release-manifest.json`; the manifest records desktop commit `a8408119c4beb49a2b15ac978c7e163c43abd3cc` and integration commit `3eb35ab40d0079cc1ac2065eb815050ca2ed1bfb`. The Windows app and installer are `NotSigned`, as disclosed in the release notes.
