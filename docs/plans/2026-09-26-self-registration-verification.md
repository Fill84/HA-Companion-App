# Self-registration upgrade verification (26 September 2026)

The local desktop candidate is **1.0.6** and the Home Assistant integration candidate is **1.0.12**. These source versions are not yet public release tags. The previously published versions remain 1.0.5 and 1.0.11 until the separate repositories are released.

The integration was installed on the live Home Assistant 2026.9.3 server after backing up its config entries, device registry, entity registry, integration storage and component code. The server reports integration 1.0.12 through its authenticated registration endpoint. Its config-flow handler is absent from Home Assistant's manual Add picker. The legacy empty `Desktop App` hub config entry was removed through Home Assistant's own API. After another Home Assistant restart, only the real Phill-PC and Beast-Unit entries remained. Their config-entry IDs, device IDs and webhook IDs were unchanged, and all **109** existing `(entity_id, unique_id, config_entry_id)` identities matched the pre-upgrade registry exactly.

The 1.0.6 Windows x64 NSIS installer was installed on Phill-PC and Beast-Unit. Installer SHA-256: `CAA94585725EA01EBF7569993AEEEF60F98BA17AAFADDA7768736ED2A60535F5`; both installed executables matched SHA-256 `A06C0F61509415ED308AA0D57914E62AE50735766304E08BE17795FA4C2AB228`. Both existing desktop device and webhook IDs were retained, the GUI ran in an interactive session, and `HaCompanionSensors` and `PawnIO` were running. The HA recorder received new numeric CPU usage and temperature values from both computers after the upgrade and after the final HA restart. Their Online entities returned to `on` after the next update cycle.

The Rust unit suite passed 49 tests (three hardware/OS-dependent tests ignored), the integration suite passed 46 tests, and Clippy passed with warnings denied. An isolated Home Assistant 2026.9.3 instance additionally exercised first and second device registration through HA's built-in config-flow API, webhook sensor updates, persistence after restart and recovery of an interrupted first registration. No clean user-profile install, macOS/Linux interactive runtime test or long-duration soak test is claimed here. HACS cannot offer 1.0.12 until the integration repository is published separately.
